# Japan Rule 観光参入MCP・データ構想 v0.1

2026-09-08。対象：日本の地方で観光事業を計画する海外事業者と、そのAIエージェント。宿泊だけでなく文化・食・自然体験を含む。今回はデータ見本と設計のみ。コスト情報は対象外。

## 商品の単位
１地域×１活動の「参入準備パック」。地域資源、実在する体験事例、関連制度の一次情報、確認事項、相談先をまとめる。法的な適用・非適用や開業可能性の最終判定は含めない。

## 最小データ構造
| レコード | 主な項目 |
|---|---|
| 地域 | region_id、国・都道府県・市町村、地区名 |
| 事例 | case_id、地域、活動種別、概要、出典、提携可否の確認状態 |
| 法規・確認事項 | topic_id、制度の国・県・市の区分、対象地域、質問、参照すべき条件、出典 |
| 相談先 | contact_id、組織、担当分野、公式URL、確認状態 |
| 出典 | source_id、URL、発行主体、該当箇所、言語、確認日、公開・改訂日（不明はnull） |
| パック | pack_id、schema_version、content_version、上記ID、入力不足、未確認事項 |

「確認条件」は情報を探すための分岐であり、法律の適用判定エンジンではない。送迎・宿泊手配・食事提供・場所利用の有無などを入力し、該当する相談質問を返す。

## MCPの利用案（未実装）
1. search_entry_cases(region_id, activity, language, limit, cursor)：無料の短い事例・対象範囲・pack_idを返す。
2. get_entry_pack(pack_id, plan_facts, language)：根拠・質問・相談先・不足情報をJSONで返す。有料候補。

既存ツール名の変更・追加はまだ行わない。課金は既存無料x402 Starterを再利用。顧客が払うのはJapan Ruleの情報取得料金。

## MCP向けに守る点
- 民間の営利サービスであり国・自治体の公式サービスではない旨を、サービス説明・購入前表示・返却パックに日英で明示する。公式資料へのリンクは行政の公認を意味しない。JSONにもoperator_disclosureを持つ。
- 表示名と安定IDを分ける。日本語原情報と英語要約を対応付ける。
- 事実、編集上の提案、未確認を区別。未確認はfalseに変換しない。
- 国・県・市の制度を別レコードで参照し、地域パックごとにコピーしない。
- 各記述にsource_idと箇所を付け、確認日と改訂日を混同しない。
- 内容変更はcontent_versionを更新。購入済み成果物の再取得は購入時の版を返す想定。
- リンク切れ・公式情報の矛盾はstatusに残す。鮮度期限と更新頻度は原価を見て決める。
- 外部のページ本文を大量保存せず、必要な事実要約と出典を保持する。
- 当初はJSONファイルで管理。件数・更新運用が増えてからDB化を判断。

## 祖谷の体験見本
架空計画：海外事業者が地元事業者と少人数のそば打ち体験を企画。会場、契約主体、食事提供者、送迎、宿泊手配は未定。

実在事例：三好市公式観光サイトの「つづき商店・古式そば打ち体験」。新規参入者の紹介事例や提携可能な募集案件とは扱わない。

返す質問：誰が旅行者と契約するか、誰が調理・提供するか、会場利用の承諾はあるか、運送・宿泊を組み合わせるか。旅行業法の参考情報は国の資料へ結び付ける。食品・会場条件は今回未調査として明示。

## 購入価値と次の確認
価値仮説は「AIが再検索・再整理せず、根拠を追える一定形式で取得できること」。構造化だけで有料優位性や需要を証明したことにはならない。
次はこのJSONを使い、架空計画から不足情報と相談質問を取り出せるか確認する。１件の内容を完成させるまで地域・活動を量産しない。
